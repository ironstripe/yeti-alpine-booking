
- Edge functions: staff-only functions call `requireRole` from `supabase/functions/_shared/staffAuth.ts`; test/debug functions call `testFunctionsDisabled` (off unless ALLOW_TEST_FUNCTIONS=true). Why: all functions run with verify_jwt=false, so authorization must be in code.
- Anonymous (anon) database access is whitelisted: only INSERT/SELECT on booking_requests (published booking form). Why: all other data must go through Edge Functions; rollback in supabase/rollback/p02_step2b_rollback.sql.
- Private lessons: one `private_appointments` row per real lesson, participants in `private_appointment_participants` (NOT NULL participant), one billing `ticket_items` line per appointment; trigger `trg_pa_ticket_item_guard` forces linked lines to mirror their appointment; `pa_*` helpers are service_role-only. Why: exact per-appointment pricing and no payroll/confirmation bypass.
- Private-lesson changes go only through the office/admin `private-appointments` Edge Function (create/move/period_update → one `pa_*` transaction with audit + `private_appointment_changed` event); instructor confirmation via `set-booking-confirmation` `appointmentId`. Why: atomic free-slot/price/confirmation rules in one place.
- Instructor HR/source import data (source links, HR raw values, staging, private portraits in bucket `instructor-hr-photos`) is readable only via `is_super_admin`/staff RLS and written only by service_role Edge Functions. Why: HR PII must never reach teachers, anon or the public `instructor-avatars` bucket.
- Instructor data access goes through `src/lib/instructorsApi.ts`: clients read only directory columns of `instructors` directly; contact/personnel fields via staff RPC `instructors_ops_list`/`instructor_ops_upsert`, pay/bank/AHV only via super_admin RPCs, own profile via `instructor_self`/`instructor_self_update`; login↔instructor via `instructor_user_links`; live status via `instructor_live_status`. Why: column-level least privilege must be server-enforced, never by frontend field selection.
