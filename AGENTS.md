
- Edge functions: staff-only functions call `requireRole` from `supabase/functions/_shared/staffAuth.ts`; test/debug functions call `testFunctionsDisabled` (off unless ALLOW_TEST_FUNCTIONS=true). Why: verify_jwt=false requires code authorization.
- Anonymous (anon) database access is whitelisted: only INSERT/SELECT on booking_requests (published booking form). Why: all other data must go through Edge Functions; rollback in supabase/rollback/p02_step2b_rollback.sql.
- Private lessons: one `private_appointments` row per real lesson, participants in `private_appointment_participants` (NOT NULL participant), one billing `ticket_items` line per appointment; trigger `trg_pa_ticket_item_guard` forces linked lines to mirror their appointment; `pa_*` helpers are service_role-only. Why: exact per-appointment pricing and no payroll/confirmation bypass.
- Private-lesson changes go only through the office/admin `private-appointments` Edge Function (create/move/period_update/edit → one `pa_*` transaction with audit + `private_appointment_changed` event); wizard edits of canonical bookings use `edit` (server quote, client acknowledgement, never `useUpdateBooking`); instructor confirmation via `set-booking-confirmation` `appointmentId`. Why: atomic free-slot/price/confirmation rules in one place.
- Canonical edit requests require original scheduler, participant and mirrored-line values per edited lesson and the original ticket note when edited; notes remain per lesson, and acknowledged participant changes apply only their discounted net delta to the stored ticket total. Why: reject stale editors before writes without flattening notes or repairing unrelated historical discrepancies.
- Instructor HR/source import data (source links, HR raw values, staging, private portraits in bucket `instructor-hr-photos`) is readable only via `is_super_admin`/staff RLS and written only by service_role Edge Functions. Why: HR PII must never reach teachers, anon or the public `instructor-avatars` bucket.
- Instructor data access goes through `src/lib/instructorsApi.ts`: clients read only directory columns of `instructors` directly; contact/personnel fields via staff RPC `instructors_ops_list`/`instructor_ops_upsert`, pay/bank/AHV only via super_admin RPCs, own profile via `instructor_self`/`instructor_self_update`; login↔instructor via `instructor_user_links`; live status via `instructor_live_status`. Why: server-enforced column-level least privilege.
- Booking-Corner Apply writes, in the same per-row subtransaction as each change, an immutable first-write entry in `instructor_import_ledger` (full pre-image for updated targets, provenance for real new UUIDs); recovery is dry-run only via service_role `bc_recovery_dry_run`, never a global restore. Why: selective recovery without restoring the shared Cloud database.
- Staff group bookings pass `groupBookingPreflight`; source-bound bookings use `staff-group-booking`. Product delete: staff `product-management` → service-only `product_delete` (usage list blocks; BC tariff sources alone don't, removed after `product_deletion_log` snapshot; FKs final guard). Why: recoverable.
- 26/27 website course bookings run only through the `bc_2627_*` SQL state machine (held→finalized→invoicing→confirmed; release only before invoicing) via the `course-booking` function; invoices come only from `issueInvoice` after `bc_2627_begin_invoice`, and e-mails only through `_shared/courseDelivery.ts` (one leased row per ticket+kind, configured sender, staff resend via `retry-course-booking-delivery`). Why: retries can never create a second invoice or e-mail, and a cancelled or expired hold is never invoiced.
- SQL/API tests load `tests/sql/production_schema_baseline.sql` and synthetic local PostgreSQL/PostgREST fixtures via psql. Why: preserve production constraints/triggers and backslashes.
- Follow `docs/ui-standard.md`; preserve workflows/data. Why: styling cannot alter office behavior.
- Private lessons: "Später zuweisen" teacher clearing lives in the pure `src/lib/assignLaterState.ts` (active cart item only, never restores a teacher, keeps scheduler provenance); the server accepts a NULL teacher only for slots with explicit `assign_later: true` (migration `drizzle/migrations/0001_pa_assign_later.sql`), and assignment happens only via move/period_update. Why: an accidentally missing teacher must never become a valid booking, and assignment keeps atomic conflict checks.
- Course delete/archive goes only through office/admin `course-management` → service_role `course_*` SQL (migration 0002): delete locks course + owned children, removes owned 26/27 source links and empty generated structure in one transaction with a `course_deletion_log` snapshot, and blocks (never cascades/SET NULL) real usage; no raw `group_courses` DELETE; rename is name-only. Why: no lost history or orphan bookings.
- `customers.email` is optional (NULL = unknown, unique when present, never blank/placeholder; migration 0009); office UI and senders must treat a missing email as "nicht senden" via `src/lib/customerEmail.ts`. Why: customers without email remain bookable.

- Pricing stays in `productEditorPricing.ts`; offerings use one atomic staff JSON RPC, exact tiers service-only. Saturday checks use `_shared/saturdaySelection.ts` with trusted level/period/tariff facts. Why: no name matching, repricing or booking release.

- Public private display tariffs use revision-checked staff saves; catalog serves verified rows only. Why: safe.

- Lunch: full-day blocks, atomic person/day items; GroupLunchSelection in both modes. Why: safe removal.
- Checkout deadlines use checkoutDueDate for display/create; only explicit dates live in wizard state. New invoices read the ticket deadline; replays retain invoice data. Why: one date without stale defaults or client invoice authority.
- Resumed invoices with frozen payment snapshots must match final routing and all associated payment columns before any write (except the historical snapshot creation timestamp). Why: documents and invoice routing must never mix different payment configurations.
- Scheduler desktop teacher shells stay mounted for search/scroll geometry; only nearby slot trees render, with active drag/resize/focus rows pinned and selection state outside rows. Why: reduce rendering load without losing planning drafts or drag sources.
- Scheduler visible teacher/absence filters are component-local, indexed display-only rules over unfiltered assignments and actual displayed dates; explicit teacher selection bypasses role/compact hiding. Why: retain inspection and planning drafts without changing conflict/write authority.
